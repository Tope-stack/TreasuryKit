# 0011 — Running the demo as a single service on a free host (Render)

- **Status:** Accepted
- **Date:** 2026-11-14

## Context

The single-VM deployment (ADR 0010) needs a paid VM. Render's free tier has the following limits:
- web services only (background workers start at a paid plan);
- no persistent disk for free web services;
- services sleep after 15 minutes idle;
- a free PostgreSQL that expires after 30 days.

TreasuryKit assumed a separate Worker process and a disk shared between the Api and the Worker.

## Decisions

1. **Background work in the Api, by setting.**
   - **The setting:** `Hosting:RunBackgroundJobs=true` makes the Api host the outbox dispatcher and the job runner, via `AddBackgroundProcessing()`, the same registration the Worker uses.
   - **Ordering:** they start after the Api applies migrations.
   - **Defaults:** the setting is off by default, so the VM and Worker setup are unchanged. Job claiming already uses leases and `SKIP LOCKED`, so running both would also be safe.
2. **Uploads in PostgreSQL, by setting.**
   - **The setting:** `FileStore:Provider=Database` stores uploads in `platform.stored_files` (a `DatabaseFileStore` behind the existing `IFileStore`). `Local` (disk) stays the default.
   - **Why it's fine:** files are capped at 20 MB and the free database has 1 GB, enough for a demo.
   - **Registration:** the Worker now also registers the platform schema, so it can read stored files whichever provider is used.
3. **URL-form connection strings.** `ConnectionStrings.Normalize` accepts `postgres(ql)://user:pass@host:port/db?sslmode=…`, as Render and others provide, and converts it to Npgsql's keyword form. Keyword strings are unchanged.
4. **The password gate moves into the Api when there is no proxy.**
   - **The middleware:** `DemoGateMiddleware` applies the same rule as the Caddy gate (ADR 0010). Requests without a bearer token need HTTP basic auth with `DemoGate:Username`/`DemoGate:Password`; `/health` stays open for Render's health check.
   - **When it runs:** only when a password is set. On the VM, Caddy keeps doing it.
5. **`render.yaml` Blueprint:**
   - **Services:** one free Docker web service built from the existing Api Dockerfile, and one free PostgreSQL, both in Frankfurt.
   - **Settings:** the `Demo` environment, `PORT=8080`, and the two settings above.
   - **Secrets:** the JWT key is generated by Render, and the database connection is injected from the database. The demo password is entered in the dashboard and never committed.

## Consequences

- **Free-tier behaviour:** the demo sleeps when idle (first visit takes about a minute), and background work pauses while it sleeps.
- **Monthly refresh:** the free database must be recreated about every 30 days, with the demo data reloaded; `docs/deploy/render.md` has the steps.
- **Still synthetic data only** (ADR 0010).
- **Moving off the free tier** is a matter of plans, not code. A paid Render worker could run the Worker image with the same database file store.
